01 About

I didn't start out planning to break applications for a living — I started out curious about how they actually worked underneath the interface, and that curiosity turned out to be the whole job. Based in Delhi, I spend my time on the offensive side of security: web apps, mobile apps, and the APIs that quietly connect them, all under the assumption that if a flaw can exist, someone will eventually find it, so it might as well be me.

The work I'm proudest of so far is leading the mobile penetration test on DigiLocker — one of the more consequential apps in the country to get right — and being trusted inside CERT-In's own examination process, where the reporting standard is as demanding as the testing itself. I recently moved into a Consultant 2 role at Protiviti's Technology & Digital – Privacy & Security practice, carrying that same instinct for "what was this system built to prevent, and where does that break" into privacy and risk consulting. Alongside all of it, I'm finishing an MCA and still deliberately spending spare hours going deeper on Android internals and web exploitation, because the checklist stops being useful the moment you actually understand the system.

05 Field Notes
Mobile Security

Why mobile pentesting needs more than a MASVS checklist

Automated scans catch the obvious. The interesting issues in Android/iOS apps usually show up when you pair MobSF's static pass with manual work in Jadx-GUI and ADB — reading the logic, not just the findings list.

Field note
API Security

BOLA is still the bug API testing keeps finding

Map every endpoint in Postman, then ask one question of each: does the object ID alone decide access? Broken Object Level Authorization keeps turning up because that question rarely gets asked early enough.

Field note
Reporting

What CERT-In style testing taught me about writing reports

A finding is only as useful as the report behind it. Working inside CERT-In examination environments pushed me to back every severity call with evidence and a CVSS score a developer can act on immediately.
